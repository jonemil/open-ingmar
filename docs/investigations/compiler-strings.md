# Compiler strings and `System.println`

2026-10-10. Question: how should independently generated strings, local reads,
and print statements connect semantic IR, CODE, and application DATA?

## Controlled SDK observations

**Experimentally observed:** SDK 9.2.0, `fr265`, `-O0`, Java 17, using the local
key. Copy Hello World and replace its `probe` body with:

```monkeyc
System.println("Generated hello # span=1:2");
var message = "héllo";
System.println(message);
System.println(40 + 2);
return 41;
```

The SDK selects `getmv @Toybox_System @println; frpush`, evaluates the argument,
then emits `invokem 2; popv`. The literal print starts at CODE+`0x3b` and uses
`news` at `0x45`, targeting DATA+`0x32b7`. Local initialization at CODE+`0x4d`
uses `news` targeting DATA+`0x3307`, then `lputv 1`; its print uses `lgetv 1`.
The integer print evaluates `40 + 2` without folding. Stored symbols are
`Toybox_System` (`0x00800005`) and `println` (`0x00800067`).

The greeting record contains tag `01`, length `001a`, 26 UTF-8 bytes, and a zero
terminator. `héllo` contains six UTF-8 bytes, despite having five characters.
This agrees with the existing [DATA string profile](../specs/data-strings.md).

A second SDK specimen uses:

```monkeyc
System.println("tab\tline\nreturn\rquote\"slash\\");
return 41;
```

Inspection finds the decoded 28-byte value at DATA+`0x3302`, containing actual
tab/newline/carriage-return/quote/backslash characters. These source escapes are
therefore observed, not inferred from our assembly escape parser. Source Unicode
escapes and other SDK modules were not investigated.

**Interpretation:** printing is an effectful statement with no semantic result;
the VM call result still needs discarding. SDK module binding should be explicit
for this intrinsic, without assuming all SDK modules follow one naming rule.
Literal content belongs in semantic IR; placement belongs in DATA assembly.

## Implementation and runtime result

[Source](../../examples/compiler-probe/strings.mc) prints a new greeting,
initializes a string local, prints it, prints `40 + 2`, prints the local again,
and returns `43`. Source parsing, typed IR validation, IR text, and VM lowering
support this together. Strings propagate through local reads; parameters,
arithmetic, user-module arguments/results, and returns remain integer-only.
Unsupported uses fail before output creation.

Lowering deduplicates content within the function and emits unplaced `.string`
requirements. `--data` binds them by unique content in an explicit DATA source;
`--symbols` binds the SDK module/member. Layout-only DATA parsing retains class
method aliases until PRG reconstruction, avoiding a CODE/DATA binding cycle. No
application metadata or numeric symbol IDs are generated by the frontend. See
[the source contract](../specs/compiler-subset.md) and
[the IR/pipeline contract](../specs/compiler-ir-text.md).

**Experimentally observed:** native source → CODE, saved IR → CODE, and saved
assembly → CODE produce identical 79-byte bodies. Appending the two generated
strings adds 58 DATA bytes at `0x3332` and `0x3358`. Their lengths are 34 and 16
UTF-8 bytes. The greeting did not exist in the scaffold; this exercises our DATA
encoder rather than only reusing SDK literals.

The signed PRG runs in Garmin's official simulator. Console output begins:

```text
Hello from Monkey C!
Hello from our compiler # span=1:2
héllo from Rust
42
héllo from Rust
43
```

The captured watch screen displays `Hello world!` and `43`. Subsequent view
updates call `probe` again and repeat its prints, as expected from the scaffold.
This confirms literal loading, string-local storage/read, integer evaluation,
result discard, and execution order for this straight-line function.

Bounded append integration: preserve old instructions and line PCs, redirect the
DATA method via its existing `probe` label, and retain signature alignment.
Generated declarations go into DATA; project CODE permits references only.

```sh
python3 - <<'PY'
from pathlib import Path
import json, re
root = Path('scratch/compiler-strings')
project = root / 'generated-project'
asm = (root / 'generated.mcasm').read_text().splitlines()
literals = [line for line in asm if line.startswith('.string ')]
added_data = sum(len(json.loads(line.split(' ', 2)[2]).encode()) + 4
                 for line in literals)
added_code = len((root / 'generated.bin').read_bytes())
padding = (-(added_data + added_code)) % 32
symbols = (project / '010-symbols-5717b015.mcasm').read_text()
bindings = []
for alias, name in [('__ciq_sdk_System', 'Toybox_System'),
                    ('__ciq_member_println', 'println')]:
    ids = re.findall(r'^\.symbol \S+ "' + re.escape(name)
                     + r'" id=(0x[0-9a-f]+) ', symbols, re.M)
    assert len(ids) == 1
    bindings.append(f'.symbol {alias} "{name}" id={ids[0]}')
code = project / '003-code-c0debabe.mcasm'
body = code.read_text()
assert body.count('\nprobe:\n') == 1
code.write_text(body.replace('\nprobe:\n', '\nprobe_original:\n') + '\n'
                + '\n'.join(bindings) + '\n'
                + '\n'.join(line for line in asm
                            if not line.startswith('.string ')) + '\n')
lines = project / '005-line_numbers-c0de7ab1.mcasm'
lines.write_text(lines.read_text().replace('pc=code:probe ',
                                          'pc=code:probe_original '))
resources = project / '007-resources-f00d600d.bin'
resources.write_bytes(resources.read_bytes() + bytes(padding))
manifest = project / 'sections.ciq'
text = manifest.read_text()
for kind, growth in [('0xda7ababe', added_data), ('0xc0debabe', added_code),
                     ('0xf00d600d', padding)]:
    pattern = rf'(section {kind} )(\d+)( )'
    assert len(re.findall(pattern, text)) == 1
    text = re.sub(pattern, lambda m: m[1] + str(int(m[2]) + growth) + m[3],
                  text)
manifest.write_text(text)
PY
target/debug/ciq-asm project scratch/compiler-strings/generated-project scratch/compiler-strings/generated-43.prg -y keys/developer_key.der
target/debug/ciq-asm verify scratch/compiler-strings/generated-43.prg -y keys/developer_key.der
sh scripts/run-simulator-container.sh --prg scratch/compiler-strings/generated-43.prg
```

## Preservation and validation

Independent section comparison confirms original CODE is an exact 803-byte
prefix; the generated function begins at `0x323`. The original DATA prefix
changes only the probe method's four-byte value at `0x49f`, from `0x10000030` to
`0x10000323`. The strings append after the original 13106 bytes. RESOURCES
retains its original 7774 bytes and gains 23 zero bytes. Only DATA, CODE,
RESOURCES, and DEVELOPER_SIGNATURE change. Existing DEBUG/line mappings refer to
preserved old bodies; no new debug maps are generated. This remains bounded
integration, not general relocation.

Both own-key signature algorithms verify. The resulting PRG exports and
reassembles byte identically without re-signing:

```sh
target/debug/ciq-dis all scratch/compiler-strings/generated-43.prg scratch/compiler-strings/roundtrip-project
target/debug/ciq-asm project scratch/compiler-strings/roundtrip-project scratch/compiler-strings/roundtrip.prg
cmp scratch/compiler-strings/generated-43.prg scratch/compiler-strings/roundtrip.prg
```
